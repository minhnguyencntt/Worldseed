# REQ-223 — REQ · checkTrackedFiles and parseGitLsFiles report tracked dependency and vitest-cache paths

## Summary
Helper file exposes parseGitLsFiles and checkTrackedFiles over a null-separated git ls-files -z listing.

## Description
Context: helper file only filters node_modules segments from a string array. Desired behavior: parseGitLsFiles splits null-separated output and drops empty entries; checkTrackedFiles(run) runs git ls-files -z and returns every path under node_modules or in the vitest cache. Expected result: one export of each name, no duplicates. Why: a single testable detection point for the guard.

## Acceptance criteria
- Given 'a\0b\0' , When parseGitLsFiles runs, Then it returns ['a','b'] with no empty entry.
- Given a runner returning 'src/a.ts\0node_modules/x.js\0', When checkTrackedFiles runs, Then it returns ['node_modules/x.js'] and the runner was called with ['ls-files','-z'].
- Given a path 'game/frontend/node_modules/.vite/vitest/results.json', When checkTrackedFiles runs, Then it is reported.
- Given the helper file, When parsed, Then each helper name is exported exactly once.
